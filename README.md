# 网媒探测 · Media Sniffer

探测网页里的视频与图片，一键下载到本地。为 iOS Safari（Userscripts / Tampermonkey）设计，桌面端同样可用。

```
media-sniffer.user.js   约 6275 行 / 200 KB，零依赖，单文件   v1.0.0（最终版）
```

## 能探测什么

| 类型 | 说明 |
|---|---|
| **HLS 视频** | `m3u8` 播放列表 + `ts` / `m4s` 分片；主列表可挑码率，AES-128 自动解密 |
| **直链视频** | mp4 / mov / avi / mkv / webm / flv 等 |
| **图片** | jpg / png / gif / webp / avif / svg 等 |
| **音频** | mp3 / m4a / aac / ogg / opus / flac / wav 等 |
| **DASH** | `mpd`（只做识别与复制链接，不合并） |

没有扩展名的地址也能认：`/img?id=123`、`/play?vid=9` 这类，靠响应头 `Content-Type`、资源计时的发起类型（`img` / `audio` / `video`）以及页面元素扫描来判断。

## 安装

1. iOS：App Store 安装 **Userscripts**（免费）或 **Tampermonkey**；桌面：Tampermonkey / Violentmonkey
2. 把 `media-sniffer.user.js` 导入脚本管理器，确认已启用
3. 打开任意网页，右下角出现渐变圆形悬浮按钮即就绪

脚本声明了 `GM_xmlhttpRequest`、`GM_getValue` / `GM_setValue` 与 `@connect *`：
跨域资源读不到时走脚本管理器的特权通道，设置也存在管理器里、换站点不丢。
首次安装时管理器可能询问一次授权，允许即可。不支持这些 API 的环境（例如部分 iOS 版本）
会自动退回页面 `fetch` 与 `localStorage`，功能基本不中断，只是跨域资源仍受页面限制。

## 使用

### 探测

- 视频**先点一下播放**，图片**滚动到可见位置**——页面一旦请求这些资源，就会出现在列表里
- 列表**只显示当前这一页**的资源，并实时跟随正在播放的媒体：站内换集（URL 变化或播放器换源）会自动清掉旧条目，正在播放的置顶并带标记
- 悬浮按钮上的红色角标实时显示已探测数量（可在设置里关闭）
- 顶部页签筛选：**全部 / 视频 / 图片 / 音频**（「视频」= 播放列表 + 分片 + 直链视频）
- 图片按**实际分辨率**过滤：任一边小于 96px 的图标类小图不进列表（另设 12KB 字节下限，挡掉小体积占位图）
- 图片覆盖：`<img>`（含 `srcset` 与 `data-src` / `data-original` 懒加载）、CSS 背景图、无扩展名 CDN 地址
- 右上角两个气泡按钮：**刷新**（清空列表与任务卡片、重新探测当前页）与**设置**
- **内嵌页合并**：页面里套 iframe（含多层嵌套）时只有最外层一个悬浮窗；内嵌页探测到的媒体逐级上报、合并进同一张列表（标注「内嵌页」），下载再逐级派回对应的内嵌页执行并回传结果
- 手势：按住面板顶部「Media Sniffer · 域名」卡片**下滑即可关闭**，实时跟手、过阈值松手收起；设置弹窗在**卡片任意位置**（滑杆等输入控件除外）下滑同样关闭，内容还能上滚时优先滚动。弹窗手势会拦下被页面 CSS/脚本抢走的竖向触摸（如 `body { touch-action: pan-y }` 的站点），任何网页上行为一致

### 下载

- 点列表项的下载按钮。HLS 流会并发抓取全部分片、按序合并、自动解密，体检通过才保存；完成提示只显示「结果 · 文件大小」
- 任务卡片跟随当前页签分类，同一类别内按下载时间倒序（最新在最上）
- **下载完成即自动保存**（可在设置里关）：桌面端完成后直接交给浏览器下载管理器落盘，无需再点一次。**iOS 例外**：无用户手势时程序化下载会把当前标签页导航成 `blob:` 文档（文件存下了，页面连同脚本都没了，刷新也回不来），因此 iOS 上自动保存改为**挂起待手势**——下载完成后轻点任务卡上的「保存文件」，即走系统分享面板存入「文件」，页面始终不被替换
- **保存成功才释放内存，且只释放这一个文件**：失败或未保存的任务原样留在内存里，随时可以再存
- **防盗链兼容**：所有媒体（视频 / 音频 / 图片）共用同一条请求链路——默认带页面完整 Referer；遇到 401/403 会依次尝试「Referer + Cookie」（同源再加 Range）、「纯净请求」、「模拟地址栏导航」几种姿势，两条通道都走完才报错
- **403 时**：任务卡只留一个「复制直链」按钮，错误提示为「HTTP 403 请「复制直链」后自行下载」——这类 CDN 只认浏览器亲自发出的请求，脚本内的任何重试都拿不到字节，复制出来交给外部工具最省事
- 扩展名推断会看 `?fname=` / `?filename=`，`/ftn_handler/<hex>/?fname=hd.mp4` 这类路径无扩展名的地址也能存成 `.mp4`
- 音频、图片、直链视频走同一套脚本内下载与保存流程；iOS 的「保存文件」走系统分享面板存入「文件」，不接管 Safari 界面
- 文件名 = 下载时间，例如 `20261114104410.ts`——按名称排序就是按下载时间排序，不会撞名
- 落盘前做播放器视角的体检：包对齐（188/192/208）→ 是否密文 → 节目表（PAT/PMT）→ 编码格式。**认不出来就报错并给出下一步，绝不产出打不开的文件**
- 加密流缺密钥时，卡片上会出现「输入密钥解密」，可就地解密，不必重新下载

### 大文件建议

浏览器内下载全程在内存里拼装。超过 1GB 的视频建议改用列表里的「复制直链 / 导出 .m3u8」，交给 VLC 或 ffmpeg 在浏览器外下载：

```bash
ffmpeg -i "粘贴的.m3u8地址" -c copy out.mp4
```

## 设置

点面板右上角的气泡齿轮打开，改动立即生效并记住。

| 设置项 | 说明 |
|---|---|
| **主题** | 十套配色：默认（首次启动即此配色）/ 白 / 黑 / 灰 / 棕 / 蓝 / 紫 / 红 / 绿 / 橙。悬浮窗颜色跟着主题走 |
| **悬浮窗不透明度** | 20%–100%，1% 一档；数值越大越不透明。任何状态下都按设定值显示 |
| **并发数** | HLS 分片同时下载的连接数（2 / 4 / 6 / 8 / 12 / 16）。只影响分片视频，直链图片 / 音频 / 单个 mp4 不受影响；浏览器同域并发约 6，8 以上仅在特权通道下有明显收益 |
| **内存提醒** | 400 / 700 / 900 / 1400 / 2048 / 3072 / 4096 MB。累计下载量超过阈值时提示一次、建议改用直链，**任务不会中止**。iOS 建议 1400 以下 |
| **悬浮窗标记** | 悬浮按钮右上角的红色数字角标；关闭后立即消失 |
| **自动保存** | 默认开。下载完成后自动落盘并释放该文件内存；关掉则成品留在内存里等你手动保存 |
| **清理缓存** | 清掉未完成 / 已取消任务留在内存里的半截分片、密文副本与任务卡片；不动已完成成品、探测列表和设置 |
| **恢复默认配置** | 全部设置回到首次启动的状态：主题「默认」、不透明度 100%、并发 4、内存提醒 900MB、标记开、自动保存开 |

## 实现要点

脚本用纯页面能力实现三层结构，不改动页面自身的任何逻辑：

- **探测层**：`PerformanceObserver(resource)` + `fetch` / `XMLHttpRequest` 钩子 + 媒体元素与 DOM 扫描。资源计时能看到页面发出的每一个资源请求，包括原生 HLS 播放器经系统网络栈发出的分片请求
- **下载层**：HLS 分片并发抓取 → 顺序拼装 → 产物体检 / 修复；直链媒体直接单请求下载；跨域优先走脚本管理器的特权通道
- **解密层**：WebCrypto AES-CBC，按 `#EXT-X-KEY` 的 IV 规则解密

几条设计约束：

- **只读探测**：不 patch `HTMLMediaElement`，只做捕获阶段监听与 `MutationObserver`
- **跨域凭据**：跨域请求默认不带 cookie（带 cookie 会与 `Access-Control-Allow-Origin: *` 冲突），需要时由重试阶梯显式加上
- **沙箱适配**：声明 `@grant` 后脚本跑在管理器的沙箱里，`window` 是代理对象——`window.top === window` 会因身份不一致恒为假，往 `window` 上写属性也不保证落到页面。因此**角色判定一律用 `unsafeWindow`（页面真实 window）**，所有权令牌、拆除入口与调试接口则**同时写入沙箱与页面两侧**，读取时取较大值
- **帧间协作**：内嵌页只探测并上报，界面只在最外层出现一份——**跨域内嵌页也不会多出悬浮球**。角色判定（页面真实 window）：`top === self` 即确定顶层；`frameElement` 拿到 iframe 元素即确定同源子帧（注意：**跨域内嵌页的 `frameElement` 也返回 null**，并不抛错，因此它不能当顶层证据）；其余情况证据不足，走 `hello` / `ack` 握手纠正——ack 必须原样回传本次 hello 的随机数，重试持续 8 秒。证据不足的帧有 **2.6 秒挂载冷静期**：真内嵌页在期间收到 ack 就根本不挂界面，等不到 ack（父帧没有脚本）冷静期一过照常挂出。子帧媒体在宿主列表里带「内嵌页」标记，通过「合并下载」把任务派回子帧执行
- **启动兜底**：看门狗在启动第一步就装好（每 2 秒检查一次，最多 60 次），无论首挂失败、节点被页面摘掉，还是从 bfcache 回来时 DOM 被还原，都会自动重新挂载
- **互相不打架**：页面被重复注入脚本时，新实例先拆掉旧实例的界面、监听与定时器，再接管

## 边界（使用前请了解）

- **DRM 内容不可下载**：Widevine / FairPlay 等 DRM 加密的站点，分片不走可解的密钥通道，脚本不会也不应尝试绕过
- **看不到请求就探测不到**：极少数播放器用 WebSocket 或私有通道喂数据，资源计时里观察不到
- **强防盗链的 CDN 只能复制直链**：某些站点校验请求来源到无法模拟的程度，脚本读不到字节时只能复制直链交给浏览器或外部工具
- **内存即上限**：能下多大的文件取决于设备能给浏览器多少内存，而不是磁盘空间
- 脚本只在本地运行，不向任何服务器发送数据

## 排查

如果某个页面没出现悬浮按钮，打开控制台执行：

```js
__tsSniffer.diag()
```

返回的对象里重点看三项：

| 字段 | 含义 |
|---|---|
| `mounted` | 界面是否真的在文档里（false 说明没挂上） |
| `isTop` / `topCertain` | 角色判定结果；`isTop:false` 说明被当成了内嵌页，这是内嵌页的正常表现 |
| `retry` / `lastError` | 看门狗重试次数与最后一次挂载异常；`retry` 已到 60 说明连续失败两分钟 |

## 目录结构

```
media-sniffer/
├─ media-sniffer.user.js   脚本本体（单文件，零依赖）
├─ README.md
├─ docs/                   界面截图
├─ dev/                    本地 demo、跨域/内嵌页样例、CDP 自动化测试
└─ tools/                  核心逻辑单元测试
```

运行测试：先 `node dev/server.mjs 8787` 启动本地 demo（同时会在 8788 起一个跨域源），再逐套执行：

```bash
node tools/test-core.mjs     # 核心逻辑单元测试
node dev/session.mjs         # 界面、探测、下载、帧协作
node dev/encrypted.mjs       # AES-128 自动解密与手工密钥
node dev/stability.mjs       # 启动稳定性压测（冷启动 / 重注入 / 摘除自愈）
node dev/ios.mjs             # iOS 保存路径（无手势不导航、挂起后手势保存、刷新仍存活）
node dev/sandbox.mjs         # 脚本管理器沙箱模拟（代理 window + unsafeWindow）
node dev/frames.mjs          # 跨域内嵌页：悬浮球合并、媒体合并、宿主页拖动
node dev/tm-live.mjs         # 真实 Chrome + 本机 Tampermonkey 端到端实测
# 另有 formats / probe / fmp4 / desktop / crossorigin / savepath
```

**须顺序执行**，并行会抢端口导致误报。
